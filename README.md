## 구현 범위

### 1. 캐릭터 & 카트 조합 물리 스탯 시스템

**오리지널 캐스트 8종** (`js/data.js`) — 체급별로 성향이 갈린다

| 체급 | 캐릭터 | 콘셉트 | 성향 |
|---|---|---|---|
| 경량급 | **삐약** | 고글 쓴 병아리 파일럿 | 가속 최상, 피격 회복 최속 |
| 경량급 | **모모** | 긴 귀를 눕히고 달리는 토끼 | 최경량 · 핸들링 최상 |
| 경량급 | **볼트** | 바이저와 안테나를 단 소형 로봇 | 경량급 중 최고속 지향 |
| 중형급 | **코코** | 등지느러미가 솟은 아기 공룡 | 전 스탯 균형 (올라운더) |
| 중형급 | **탱고** | 파일럿 헬멧을 쓴 여우 | 중형급 속도형 |
| 중형급 | **루나** | 금빛 눈의 보라 고양이 | 중형급 핸들링형 |
| 중량급 | **범퍼** | 상아빛 뿔의 코뿔소 | 충돌 밀어내기 강함 |
| 중량급 | **마그마** | 균열로 용암이 흐르는 암석 골렘 | 최고속·무게 최상, 가속·핸들링 최하 |

경량급은 가속·핸들링·오프로드 마찰이 높고 최고속이 낮으며,
중량급은 그 반대입니다. 스탠다드 프레임을 고르면 카트가 캐릭터 시그니처 컬러를 입습니다.

**파츠 합산** (`js/stats.js`)

```
최종 스탯 = [캐릭터 Base] + [카트 프레임] + [바퀴] + [글라이더]
합산 스탯 = 최고속(speed) · 가속(accel) · 무게(weight) · 핸들링(handling) · 오프로드 마찰(offroad)
```

합산된 0~10 스케일 스탯은 `Stats.toPhysics()`에서 실제 주행 물리 제어 값으로 변환되어
매 프레임 적분에 사용됩니다.

| 물리 제어 값 | 산출식 | 용도 |
|---|---|---|
| `mass` | `62 + weight × 17` | 카트 간 충돌 밀어내기, 관성 |
| `inertia` | `0.55 + weight×0.06 − handling×0.02` | 회전 관성(조향 반응 둔화) |
| `maxTorque` / `accelRate` | 가속 스탯 기반 | 엔진 토크 → 가속도 |
| `maxSpeed` | `296 + speed × 25` | 최고 속도 |
| `tireFriction` / `driftFriction` | 핸들링 기반 | 타이어 횡마찰 계수 |
| `offroadGrip` | `0.34 + offroad × 0.049` | 오프로드 최고속 배율 |
| `recoverScale` | 가속 스탯 반비례 | 피격 후 회복 속도 |

파츠 6종 프레임 · 5종 바퀴 · 4종 글라이더 = **8 × 6 × 5 × 4 = 960가지 조합**.

### 2. 순위 기반 아이템 드롭 가중치 알고리즘 (`js/items.js`)

아이템 상자와 충돌하면 **그 순간의 실시간 순위(1~8위)** 로 확률 테이블을 조회합니다.

| 순위 구간 | 배정 성향 | 주요 아이템 |
|---|---|---|
| 1위 | 방어 / 트랩 | 바나나, 그린 셸, 동전 |
| 2~3위 | 견제 / 단거리 추격 | 레드 셸, 버섯, 그린 셸 |
| 4~6위 | 역전용 이동기 / 범위기 | 트리플 버섯, 폭탄, 로켓, 스타 |
| 7~8위 | 광역 / 특수 고확률 | 스파이크 셸, 번개, 로켓, 스타 |

**룰렛 연출**: 획득 즉시 가중치 알고리즘으로 결과를 확정하되, 1.5초 동안 아이콘을
무작위로 회전시키고(끝으로 갈수록 감속) 연출 종료 직전 최종 아이템을 슬롯에 장착합니다.
참가자가 8명 미만이면 최하위가 테이블 끝에 닿도록 순위를 정규화합니다.

### 3. FSM 기반 피격 반응 (`js/kart.js`)

| 상태 | 트리거 | 동작 | 복귀 |
|---|---|---|---|
| `NORMAL` | — | 입력(가속/브레이크/드리프트)에 정상 반응 | — |
| `SPINOUT` | 바나나 · 그린 셸 | 전진 추진력 **즉시 0**, Y축 **720° 회전** | 1.5초 후 가속도 0부터 재상승 |
| `KNOCKBACK` | 폭탄 · 스파이크 셸 · 스톰퍼 | 수직/수평 **임펄스**로 공중에 떠서 회전하며 튕겨나감. **소지 아이템·동전을 필드에 강제 드롭** | 착지 후 회복 단계(체급별 `recoverScale`) → `NORMAL` |
| `SHRUNK` | 번개 | 사용자를 제외한 전원 **스케일 0.5배**, 최고속·가속 **40% 감쇄**, 소지 아이템 즉시 파괴 | 5초 (마지막 0.5초 동안 크기 복원) |
| `RESPAWN` | 코스 이탈 · 허공 추락 · 용암 | 레스큐 드론이 중심선으로 복귀시킴 | 1.4초 |
| `BULLET` | 로켓 사용 | 무적 자동 주행, 접촉한 상대를 스핀아웃 | 4.6초 |

드롭된 동전은 실제로 필드에 흩어져 다른 카트가 주워갈 수 있습니다.

### 트랙 — 세 코스 모두 다른 주행 루트

트랙은 좌표를 손으로 찍는 대신 **[직선 / 코너] 시퀀스**로 정의합니다.

```js
layout: [
  ['s', 3500],        // 직선 3500
  ['r', 480, 70],     // 반경 480 으로 우회전 70°
  ['r', 140, 170],    // 반경 140 헤어핀
]
```

빌드 시 ① 순회전이 정확히 360°가 되도록 코너 각도를 정규화하고,
② **직선 길이를 가중 최소자승으로 풀어 폐곡선을 정확히 닫습니다**
(헤딩이 고정되면 폐합 오차는 직선 길이에 대해 선형이라 해석적으로 풀립니다).
덕분에 코너 반경은 설계값 그대로 유지되면서 코스가 어긋나지 않습니다.
부스터 발판 · 아이템 박스 · 스톰퍼는 곡률을 분석해 **직선 구간에 자동 배치**되므로
레이아웃을 고쳐도 따라옵니다.

| 트랙 | 난이도 | 길이 | 코스 성격 |
|---|---|---|---|
| **에메랄드 서킷** | ★ | 10.3k | 3500 메인 스트레이트 → 고속 1코너(R480) → 중속 2코너 → **R140 헤어핀** → 에스자 → 백스트레이트 → **시케인(R170)** → 더블 에이펙스. 정통 그랑프리 리듬 |
| **프리즘 로드** | ★★★ | 12.8k | **2500 · 1900 초장거리 직선** 끝마다 R230 급브레이크가 기다리고, 중반에 **R170 헤어핀**. 펜스가 없어 밀려나면 추락 |
| **마그마 성채** | ★★★ | 11.9k | R160 직각 코너로 시작해 **좌우 반대 방향 스위치백 2회(R145)**, 성문을 관통하는 1560 직선. 스톰퍼가 내려찍는 테크니컬 코스 |

세 코스 모두 반복 원형 루프가 아니라 서로 다른 코너 구성과 리듬을 가지며,
3랩 기준 한 판이 **90~120초** 걸립니다. 월드는 5000×5000 유닛입니다.

트랙 표면(도로 / 커브 둔턱 / 갓길 / 부스터)은 3D 리본 메시와 **같은 스플라인·같은 폭**으로
2048px 노면 판정 맵에 구워지므로, 보이는 그대로 물리 판정이 이뤄집니다.

## 동작 (`js/rig.js`)

### 카트 서스펜션

차체를 바퀴와 분리된 노드로 두고 **스프링-댐퍼**로 움직입니다. 바퀴는 지면에 남고
차체만 기울어 실제 서스펜션처럼 보입니다.

| 상황 | 반응 |
|---|---|
| 풀가속 | 노즈 업 (pitch −0.09), 뒷바퀴 쪽 차체 침하 |
| 브레이크 | 노즈 다이브 (pitch +0.11), 앞바퀴 트래블 −1.9 |
| 코너링 | 바깥쪽으로 롤 (±0.03), 드리프트 중 추가 기울기 |
| 착지 | 히브 스프링에 충격을 넣어 차체가 꿀렁 |

가속도는 속도 미분을 저역 통과시켜 구하고, 스프링은 약간의 오버슈트를 남겨
정지 화면에서도 살아 있게 보이도록 했습니다.

### 2차 모션 (관성으로 늦게 따라오는 부위)

귀 · 꼬리 · 스카프 · 안테나를 스프링 관절에 매달아 **가감속과 조향에 뒤늦게 반응**하게
했습니다. 모모의 긴 귀는 가속하면 뒤로 눕고 브레이크에서 앞으로 쏠리며 코너에서 옆으로
휩니다. 탱고·루나의 꼬리, 삐약의 스카프와 꽁지깃, 볼트의 안테나도 같은 방식입니다.

### 카메라

코너에서 카메라가 살짝 기울고(±0.055 rad), 착지 순간 아래로 꿀렁 내려갔다 돌아옵니다.
속도·부스터에 따른 FOV/거리 변화, 피격 흔들림은 기존과 동일합니다.

## 표정 (`js/rig.js`)

얼굴이 고정돼 있으면 아무리 잘 렌더해도 인형으로 보입니다. 눈꺼풀과 눈썹을
각각 관절로 달아 주행 상태에 따라 움직입니다.

| 상황 | 표정 |
|---|---|
| 정지 | 눈 크게 뜸, 눈썹 수평 |
| 고속 주행 | 바람에 눈을 가늘게 뜸 (속도에 비례) |
| 드리프트 | 눈썹 안쪽이 내려가며 결연해짐 |
| 부스트 | 더 강하게 찡그림 + 눈썹 하강 |
| 피격 | 눈이 커지고 눈썹이 확 올라감 (놀람) → 서서히 복귀 |
| 평상시 | 2.6~6.2초마다 0.16초 깜빡임 (캐릭터마다 주기가 어긋남) |

눈꺼풀은 눈알을 감싸는 위쪽 반구 껍질이고, `rotation.z` 의 **+** 방향이 감는
쪽입니다. 눈썹은 `side * (-)` 가 화난 각도입니다. 둘 다 좌표계를 직접 렌더해
확인한 값입니다. 깜빡임은 스프링 밖에서 더합니다 — 스프링을 통과시키면
0.16초짜리 빠른 동작이 뭉개집니다.

카트 한 대당 메시 41 → 45 개 (눈꺼풀 2 + 눈썹 2).

## 착좌 드라이버 리그 (`js/rig.js`)

드라이버는 **관절 계층 + 2본 IK** 로 움직입니다. 외부 모션 캡처 에셋 없이
운전 자세를 직접 구현했습니다.

```
pelvis ─┬─ torso ─┬─ head
        │         ├─ armL(upper → elbow → fore → hand)
        │         └─ armR
        ├─ legL(thigh → knee → shin → foot)
        └─ legR
```

* **두 손이 실제 스티어링 휠 그립을 잡습니다** — 매 프레임 어깨에서 휠 림 위의
  그립 좌표까지 2본 IK(코사인 법칙 + 폴 벡터)를 풀어 팔꿈치를 바깥아래로 굽힙니다.
  핸들을 꺾으면 그립이 회전하고 손도 따라 돕니다 (검증: 손–그립 오차 0)
* **다리는 착좌 포즈** — 허벅지는 앞으로 눕고 정강이는 아래로 꺾여 발이 페달에 놓입니다
* **상체**는 코너에서 롤, 가속·브레이크에서 피치. **머리**는 코너 안쪽을 보고
  속도에 비례해 흔들립니다
* **피격 반응** — 스핀아웃/넉백 시 IK 를 풀고 팔을 위로 흔들며 상체가 들썩입니다
* **정차 중 숨쉬기** — 속도가 낮으면 상체가 천천히 오르내립니다
* **머리**는 스프링으로 코너 안쪽을 살짝 늦게 따라봅니다 (오버슈트 포함)
* **관절 단위 병합** — `userData.joint` 이 붙은 노드가 병합 경계가 되어, 관절 안쪽
  메시만 머티리얼별로 합쳐집니다. 움직이지 않는 골반·다리는 카트 본체와 함께 병합돼
  드로우콜을 아낍니다 (8대 풀 그리드 713~799 드로우콜)
* 카메라에서 700 유닛 이상 떨어진 카트는 IK 계산을 건너뜁니다

## 배경 (`Models.buildBackdrop` / `Renderer._displace`)

세 코스의 배경을 각각 다른 세트로 구성했습니다.

* **지형 기복** — 지면을 평면 대신 120×120 격자로 깔고, **트랙 중심선까지의 거리**로
  변위를 줍니다. 코스 주변 560 유닛은 평평하게 유지하고 멀어질수록 2옥타브 값 노이즈로
  완만한 언덕이 솟습니다. 프롭이 언덕에 파묻히지 않도록 배치 반경을 평탄 구역 안에 둡니다
* **도로를 가로지르는 게이트** — 스타트 라인과 직선 구간 3곳에 테마별 구조물이 서고
  그 아래를 통과합니다. 서킷은 강철 갠트리 + 체커 스트립, 프리즘은 네온 링,
  마그마는 화로를 얹은 석조 아치
* **테마별 대형 배경물**
  * 에메랄드 서킷 — 피트 빌딩, 관중 타워 3기, 언덕 위 나무숲 14군데, 떠다니는 열기구 5개
  * 프리즘 로드 — 아래로 뾰족한 크리스털 부유섬 16개(자전), 고리 행성 2개, 혜성
  * 마그마 성채 — 분화구가 발광하는 화산 4개, 수호 석상 6기, 성벽 5면

## 렌더링 (three.js)

* **WebGL 실시간 3D** — `WebGLRenderer` + ACES Filmic 톤매핑 + sRGB 출력,
  PCF Soft 그림자, `EffectComposer` + `UnrealBloomPass` 블룸
* **환경맵 (IBL)** — 하늘 + 지면 반구 + 태양 + 지평선 띠로 작은 씬을 만들어
  `PMREMGenerator` 로 굽습니다. `metalness` 와 `clearcoat` 는 **반사할 주변광이
  있어야** 의미가 생기므로, 환경맵이 없으면 아무리 반짝이게 설정해도 전부 무광
  점토처럼 렌더됩니다. 게임 화면은 실제 하늘 텍스처를 그대로 넣어 반사가 배경과
  어긋나지 않게 하고, 태양 구체를 키라이트와 같은 방향에 두어 하이라이트 방향을
  맞춥니다. 로비 · 아이콘은 스튜디오 조명 프리셋을 씁니다
* **재질 분리** — 차체는 금속이 아니라 *유전체 + 클리어코트*(자동차 도색),
  휠은 금속, 타이어는 시언 있는 고무, 캐릭터 몸은 플러시 시언, **눈동자는
  거의 거울에 가까운 클리어코트**로 또렷한 캐치라이트가 박히게 했습니다
* **미세 표면 결** (`js/surface.js`) — 완벽하게 균일한 표면은 아무리 잘 비춰도
  점토로 읽힙니다. 오브젝트 공간 3D 노이즈를 셰이더에 주입해 거칠기와 알베도를
  아주 조금 흔듭니다. UV 에 의존하지 않아 지오메트리를 병합해도 살아남습니다
* **근사 앰비언트 오클루전** — 파츠마다 바운딩 구를 뽑아 정점에서 그 구들이 가리는
  입체각을 더해 가려짐을 계산하고, 정점 색으로 구워 확산광만 어둡게 합니다.
  목 · 겨드랑이 · 바퀴집 · 시트 뒤가 파묻혀 보이게 하는 부분입니다.
  겹치는 프리미티브가 수십 개라 단순 합산하면 전부 바닥값에 눌러붙으므로
  포화 곡선으로 눌러 대비를 살립니다
* **림 라이트** — 해와 반대쪽에서 실루엣 가장자리만 밝히는 그림자 없는 조명.
  캐릭터를 배경에서 떼어놓습니다
* **실제 HDRI (선택)** — `assets/manifest.json` 의 `env` 에 `.hdr` 파일을 적어두면
  절차적 환경맵 대신 그걸 굽습니다. 아래 "실제 HDRI 로 반사 올리기" 참고
* **절차적 모델** — 몸통은 **회전체(LatheGeometry)** 로 허리에서 가슴으로 부풀었다가
  어깨에서 목으로 좁아지는 단면을 돌려 만들고, 팔다리는 **끝으로 갈수록 가늘어지는
  테이퍼 뼈대**(원통 + 양 끝 반구를 한 지오메트리로 병합)로 만듭니다.
  균일한 캡슐·구 조합보다 훨씬 유기적으로 보입니다.
  삐약의 이마 고글과 휘날리는 스카프, 볼트의 발광 바이저와 가슴 LED 게이지,
  마그마의 발광 균열과 그을린 뿔처럼 캐릭터별 특징을 개별 형상으로 넣었습니다.
* **드로우콜 최적화** — 카트의 정적 파트는 관절 단위로 지오메트리 병합,
  트랙 장식물은 `InstancedMesh`, 배경물은 머티리얼 공유 후 병합. 8대 풀 그리드에서 713~799 드로우콜
* **적응형 품질** — 프레임레이트를 1.4초마다 측정해 낮으면
  블룸 → 표면 결 셰이더 → 시언 → 그림자 해상도 → 픽셀 비율 순으로
  4단계 자동 강등(회복 시 복귀). 표면 결과 시언은 픽셀당 비용이 커서
  단계가 내려가면 셰이더를 다시 컴파일해 아예 빼버립니다.
  로비에서 `자동 / 최고 / 높음 / 보통 / 낮음` 으로 고정할 수도 있다
* **GPU 진단** — `F3` 로 실제 사용 중인 GPU 이름, FPS, 드로우콜, 품질 단계를 표시한다.
  `WEBGL_debug_renderer_info` 로 렌더러 문자열을 읽어 SwiftShader · llvmpipe 같은
  **소프트웨어 렌더링을 감지하면 경고하고 품질을 즉시 최저로 내린다**
  (브라우저 하드웨어 가속이 꺼져 있을 때 프레임이 왜 안 나오는지 바로 알 수 있다)
* **하늘** — 정거원통(equirect) 캔버스로 굽습니다. 위 절반이 하늘, 아래 절반이 지면이고
  가운데가 지평선입니다. 해는 키라이트와 같은 방향에 그려 넣어 그림자 방향과
  하이라이트가 어긋나지 않고, 구름은 지평선에 가까울수록 작고 납작해져 원근이
  생깁니다. 좌우 끝이 이어지는 텍스처라 가장자리를 넘는 그림(해 글로우 · 구름)은
  -W / 0 / +W 세 번 그려 감싸야 세로 이음매가 안 생깁니다
* **지평선 산줄기** (`Models.buildHorizon`) — 지면 평면이 하늘과 만나는 자리가
  직선으로 뚝 끊기면 배경이 대번에 싸구려로 보입니다. 거리가 다른 커튼 세 겹을
  둘러 그 선을 가리고, 멀수록 안개색에 가깝게 정점 색을 구워 공기원근을 만듭니다.
  해 방향 능선은 밝게, 반대쪽은 어둡게 미리 구워 넣어 조명 없이도 입체로 보입니다.
  세 겹 합쳐 드로우콜 3개
* **타일 감추기** — 같은 타일을 넓은 바닥에 깔면 텍스처 안의 큰 얼룩이 격자로
  드러납니다. 텍스처에는 잔결만 남기고, 큰 스케일 변화는 지형 정점 색
  (`_displace`) 이 맡습니다. 주기가 다르므로 규칙성이 깨집니다
* **트랙 메시** — 스플라인 노드에서 도로 · 커브 둔턱 · 갓길 리본 메시를 생성.
  프리즘 로드는 정점 색으로 무지개 그라데이션을 입히고 `TubeGeometry` 네온 레일을 두릅니다.
* **텍스처** — 아스팔트/잔디/석재/용암/무지개 유리 텍스처를 캔버스에 그린 뒤
  Sobel 필터로 노멀맵까지 파생시켜 굽습니다. 용암은 전부 주황으로 채우면 화면이
  한 색으로 떠서 성의 검은 실루엣이 죽으므로, 식어 굳은 암반을 깔고 그 틈으로만
  용암이 흐르게 그립니다(발광맵은 균열만 켭니다).
* **UI 아이콘** — 아이템 아이콘과 로비 파츠 썸네일은 오프스크린 WebGL 렌더러로
  3D 모델을 구워 캔버스로 뽑아 씁니다(이모지 폰트 의존 없음).

## 실제 HDRI 로 반사 올리기 (선택)

환경맵은 기본적으로 코드에서 절차적으로 굽습니다(하늘 + 지면 + 태양 + 지평선 띠).
여기에 **실제 촬영된 HDRI** 를 넣으면 반사에 들어가는 정보량이 비교가 안 되게
많아져서, 같은 모델도 훨씬 입체적으로 보입니다. 넣는 방법:

1. CC0 HDRI 를 하나 받습니다 (예: [Poly Haven](https://polyhaven.com/hdris) —
   전부 CC0 라 출처 표기 없이 써도 됩니다). **1k 또는 2k 해상도면 충분**합니다.
   4k 이상은 굽는 데만 오래 걸리고 화면에선 차이가 거의 없습니다
2. **`assets/env/env.hdr`** 로 저장합니다. 끝입니다 — 설정 파일은 필요 없습니다

트랙마다 다른 HDRI 를 쓰고 싶을 때만 `assets/manifest.json` 을 만듭니다
(`assets/manifest.example.json` 을 복사해서 고쳐도 됩니다).

```json
{
  "env": {
    "default": "env/studio.hdr",
    "circuit": "env/sunny.hdr",
    "bowser":  "env/volcano.hdr"
  }
}
```

`default` 만 적으면 모든 트랙이 그걸 씁니다. 트랙별 키(`circuit` / `bowser` /
`rainbow`)를 적으면 그 트랙만 덮어씁니다. 파일이 없거나 로딩에 실패하면
**조용히 절차적 환경맵으로 돌아갑니다** — 게임이 깨지지 않습니다.

> ⚠️ 브라우저 보안 정책상 `file://` 로 열면 외부 파일을 못 읽습니다.
> `npx http-server` 같은 로컬 서버로 띄워야 HDRI 가 적용됩니다.
> `.hdr` (Radiance RGBE) 만 지원합니다. `.exr` 은 읽지 못합니다.

## 외부 3D 모델 넣기 (선택)

기본은 전부 절차적 생성이지만, **`assets/manifest.json` 을 만들고 GLB / glTF / FBX 를
넣으면 해당 캐릭터·프롭을 통째로 대체**할 수 있습니다. 매니페스트가 없으면
아무 일도 일어나지 않습니다.

```jsonc
{
  "characters": { "koko": { "file": "characters/koko.glb", "height": 34, "yaw": 90 } },
  "props":      { "tree": { "file": "props/tree.glb", "height": 90 } }
}
```

* 불러온 모델은 **바닥 접지 + 중심 정렬 + 목표 높이**로 자동 정규화되고,
  정면(+X)까지 맞춰집니다
* 애니메이션이 들어 있으면 `AnimationMixer` 로 자동 재생 (스킨드 메시는 지오메트리
  병합 대상에서 자동 제외)
* **Draco 압축 GLB** 도 `vendor/draco/` 디코더로 바로 읽힙니다
* 반대로 로비 프리뷰의 **⬇ GLB** 버튼을 누르면 현재 캐릭터+카트를 GLB 로 내보내
  블렌더 등에서 다듬은 뒤 되돌릴 수 있습니다
* `file://` 로 열면 브라우저가 외부 파일을 못 읽습니다. 에셋을 쓸 땐 로컬 서버로 띄우세요

> ⚠️ **외부 모델은 절차적 리그를 대체합니다.** 캐릭터를 통째로 바꾸는 것이므로
> 핸들을 잡는 팔 IK, 표정(눈꺼풀·눈썹), 귀·꼬리 관성 흔들림이 **같이 사라집니다.**
> 모델 자체에 스켈레탈 애니메이션이 들어 있으면 그건 `AnimationMixer` 로 재생되지만,
> 없으면 운전석에 가만히 앉아 있게 됩니다. 조각된 디테일이 필요한 게 아니라면
> 절차적 캐릭터를 그대로 두는 편이 화면에서는 더 살아 있어 보입니다.

에셋 출처별 라이선스와 옵션 전체는 [`assets/README.md`](assets/README.md) 참고.
상용 게임에서 립한 모델은 넣지 마세요.

## 밸런스 (AI 자동 주행 시뮬레이션 측정치, 8대 70초)

| 트랙 | 랩 타임 | 3랩 총 시간 | 코스 이탈 | 리스폰 |
|---|---|---|---|---|
| 에메랄드 서킷 | 27~33초 | ~88초 | 0.4% | 0회 |
| 프리즘 로드 | 31~42초 | ~105초 | 3.4% | 12회 |
| 마그마 성채 | 27~44초 | ~115초 | 4.2% | 9회 |

AI는 노드 개수가 아니라 **거리와 코너 반경**을 기준으로 판단합니다.
목표 속도는 물리 엔진의 속도 비례 조향 감쇠까지 역산해서 구합니다.

```
v = R · steerRate · (1 − 0.42 · v/vmax)   →   v = R·steerRate / (1 + 0.42·R·steerRate/vmax)
```

드리프트는 **이미 코너 안에서 그 방향으로 조향 중일 때만** 겁니다.
직선에서 드리프트를 걸면 횡슬립이 붙어 그대로 코스 밖으로 밀려나기 때문입니다.
